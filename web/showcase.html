The question, and the one it replaces

The obvious question is which filings move a stock up. It is also the wrong one: direction is a bet against desks with faster data, better models and more capital, and losing that bet quietly is the normal outcome.

So the question here is narrower and answerable. An analyst covering two hundred issuers cannot read every 8-K. Which ones deserve a human read? That is a ranking over reaction size, not sign — and unlike direction, it is something a model can actually learn.

The distinction changes what counts as success. A direction model is only useful if it beats the market. A triage model is useful if it beats reading the filings in the order they arrive.

Every bug made the number better

An AUC near 0.9 on public disclosures would be a remarkable finding. It was instead four separate defects, and not one of them announced itself — because the failure mode of leakage is not a crash. It is a result you are pleased with.

Two rows look wrong, and both are findings rather than defects.

The universe row does not move at all — 0.262916 before and after, to six decimals. That is the survivor sample confessing: when every issuer in the file still exists, a point-in-time membership filter has nothing to remove. The pipeline reports its own blind spot instead of hiding it.

The entry row moves up. Correcting the entry also corrects the window the outcome is measured over, so it sharpens the label as well as removing the impossible trade. Which is exactly why that stage's real result is not its effect on the score.

The bug no metric catches

EDGAR gives you three timestamps and only one of them is a knowledge time. Use the filing date instead of the acceptance timestamp and the score barely twitches — while the pipeline buys at an opening print that had already happened.

There is a second trap inside the right field. EDGAR serves acceptance times as 2024-10-31T18:03:31.000Z — but the clock is the SEC's, which runs on America/New_York. Parsing that Z as UTC shifts every filing five hours earlier and silently reclassifies the after-hours population as intraday.

How the reaction is measured

A standard market-model event study, with one deliberate gap in it.

The reaction is |CAR| / residual sd — expressed in standard deviations of that issuer's own noise, so a sleepy utility and a biotech land on the same scale. A filing is "worth reading" if that lands in the top decile, a threshold computed once over the whole sample and never re-estimated inside a fold.

Features, and one leakage decision inside them

What kind of news

8-K item codes — assigned by the registrant, available the instant the filing lands.

When it landed

Pre-market, intraday, after the close, or a non-trading day. Release timing is a choice the issuer makes.

How unusual

Cosine distance from the issuer's own previous filings. Boilerplate scores near zero.

Issuer state

Trailing volatility, relative volume, filing cadence — all ending the session before entry.

Novelty uses a stateless HashingVectorizer, not TF-IDF — and that is a leakage decision, not a performance one. TF-IDF has to be fitted, and a vectorizer fitted over the whole corpus carries document frequencies computed from filings that had not been written yet.

The large line is the honest cost of the split: walk-forward tests folds 1…n, so the earliest block is only ever training data. Shuffled K-fold scores all 11,681 — by training on the future to do it.

What this does not claim

No return prediction. Direction is never modelled. No strategy return, Sharpe ratio or P&L appears anywhere in the repository.

Survivorship is not controlled on the real-data path. The universe is 200 hand-picked large caps that still exist — which is why the point-in-time row above does not move. That leak is measured on the synthetic corpus instead, where membership is generated with issuers that join and leave. The universe file records the limitation in a sidecar, the ingest carries it into the run's provenance, and the report states it in a banner.

Daily bars only. The entry rule — first open at or after the decision time — is the most conservative convention available at that resolution.

Guards that raise, not warn

A check that can be ignored is a comment. Three of the four bugs are invisible in the code and visible only in the metric; the fourth is invisible in the metric and visible only in the data. That asymmetry is the argument for checking mechanically rather than carefully.

  • LeakageAudit raises, it does not log — and it runs on every pipeline execution, not in a notebook someone ran once.
  • cli audit is a CI job, so a regression fails a build rather than a quarterly review.
  • The correct configuration is the default. A safe default you have to opt into is not a safe default, and a test asserts it.
  • The real-data path runs end to end in the suite with the network faked — which is how three crashes that would have hit the first live pull were found.

Reproducing it

git clone https://github.com/josephwang-ds/ai-quant-signal-platform
python3 -m venv .venv && source .venv/bin/activate
make install
make demo        # synthetic corpus · ~4 min · no credentials, no network

export EDGAR_USER_AGENT="Your Name you@example.com"
make universe && make doctor && make ingest && make run

Every report states in its own banner which of the two paths produced it, so a synthetic run cannot be mistaken for a real one at a glance.
